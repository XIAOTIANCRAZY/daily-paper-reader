## 摘要
我们提出 LiteReality-Agent，一个智能体系统，用于从 RGB-D 扫描中将真实室内环境重建为逼真、具有铰接结构且可直接用于仿真的三维场景。其核心在于，LiteReality-Agent 将三维重建形式化为一个编码问题：编码智能体使用专用工具收集证据，并迭代编辑一个 Python 脚本 Room.py，执行该脚本即可生成房间的三维数字孪生。基于这一形式化方法，我们开发了一个稳健的“观察—编辑—验证”框架，支持在整个重建过程中进行证据收集、测量、验证、布局优化、仿真就绪性检查和质量控制。LiteReality-Agent 能生成适用于仿真和下游具身 AI 任务的高质量重建结果。此外，随着智能体能力持续快速提升，LiteReality-Agent 所引入的系统仍将是未来智能体的强大编排框架：它为其配备专用工具、结构化工作流和稳健的验证机制，从而大幅提升重建质量和可靠性。我们证明，与近期前沿模型（如 Astra 和 Fable）生成的重建结果相比，LiteReality-Agent 生成的重建结果在几何上更准确、视觉上更逼真，并且与仿真更兼容。因此，我们将 LiteReality-Agent 视为构建稳健的真实到仿真（real-to-sim）系统的实用且重要的基础模块。源代码和数据采集应用程序均已公开。代码：https://github.com/LiteReality/LiteReality-Agent/

## Abstract
We present LiteReality-Agent, an agentic system for reconstructing real indoor environments as realistic, articulated, and simulation-ready 3D scenes from RGB-D scans. At its core, LiteReality-Agent formulates 3D reconstruction as a coding problem, in which a coding agent gathers evidence using specialised tools and iteratively edits a Python script, Room.py, which can be executed to produce a 3D digital twin of the room. With this formulation, we develop a robust observe-edit-verify harness that supports evidence gathering, measurement, verification, layout optimisation, simulation readiness, and quality control throughout the reconstruction process. LiteReality-Agent produces high-quality reconstructions suitable for simulation and downstream embodied AI tasks. Furthermore, as agent capabilities continue to improve rapidly, the system introduced by LiteReality-Agent remains a strong orchestration framework for future agents: it equips them with specialised tools, structured workflows, and robust verification mechanisms that substantially improve reconstruction quality and reliability. We demonstrate that LiteReality-Agent produces reconstructions that are more geometrically accurate, visually realistic, and simulation-compatible than those generated by recent frontier models, such as Astra and Fable. We therefore view LiteReality-Agent as a practical and important building block for robust real-to-sim systems. Both the source code and the data-capture application are publicly available.   - 现有 LLM 场景生成工作（Holodeck、SceneCraft、SceneSmith、Articraft、Real2Code 等）多依赖语言先验或程序化生成，**缺乏与真实观测的紧密锚定**。
- **核心缺口**：缺少一个既能**编排智能体能力**、又能**将输出锚定在真实世界观测上**，并保证结果一致高质量、可用于目标应用的系统。
- **整体含义**：作者将 3D 重建重新表述为**编码任务（coding problem）**，把整个房间表示为一个可执行的 `Room.py` 程序，从而让智能体在可读、可复现、可直接编辑的表示空间中工作，构建稳健的 real-to-sim 基础模块。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想：重建即编码
- 房间被表示为一个**可执行的 Python 程序 `Room.py`**，作为智能体的**持久工作区**。
- 智能体通过专用工具采集证据、修改程序，编译后即得到 3D 场景；所有修改都通过同一可执行表示完成，因此场景始终**可读、可复现、可编辑**。
- 总体流程分两个阶段：**场景初始化（Scene Initialisation）** 与 **智能体作者化（Agentic Authoring）**。

### 2.2 阶段一：场景初始化
- **输入**：来自 LiteReality Scan 应用的 RGB-D 扫描与检测结果（房间布局 + 物体包围盒）。
- **Layout Agent（布局智能体）**：
  - 将布局表示为**场景图**，节点含房间、结构面、开口、物体；关系包括支撑（support）、墙面邻接、功能分组、潜在冲突。
  - 区分**物理支撑**与**功能关联**（如椅子属于桌子功能组但支撑于地面），并区分**不兼容重叠**与**预期盒体重叠**（如椅子塞入桌下）。
  - 几何检查识别越界、嵌入墙体、无支撑、不兼容重叠的物体；确定性修复做小幅位移/尺寸调整，图像推理处理歧义情形（如尺寸错误或合并的检测框）。
  - 修复受限：水平位移上限 0.6 m，垂直位移上限 0.08 m；桌/椅/沙发/床等类别尺寸变化 ≤15%，其他类别 ≤35%；不超过 6 轮智能体辅助。
- **物体重建**：
  - 选定拍摄视角 → 图像生成模型生成干净参考图。
  - **结构化/铰接物体** → 走程序化生成分支（遵循 Articraft 范式，编码智能体编写 `object.py`，定义几何、可动部件与关节）。
  - **视觉复杂且基本静态的物体** → 使用 TRELLIS.2 图像到 3D 生成。
  - 网格质量检查：异常长宽比、分离碎片、大片平坦边界、底部密集几何；椅子设有**有界重试循环**。
  - **物理属性估计**：保留作者给定值；否则按类别与尺寸估质量、按几何估惯量、按材料先验估摩擦；生成凸碰撞几何并做单物体仿真检查。
- **场景程序**：外壳与重建物体按校正后的尺度与位姿装配，`Room.py` 定义房间、物体实例、材质与新增几何；程序化资产保留其 `object.py`。

### 2.3 阶段二：智能体作者化（Observe–Edit–Verify）
- **算法流程（Algorithm 1）**：
  1. 初始化环境 `Room.py` 与工具集；
  2. 扫描获取观测；
  3. 循环（至多 T 轮，或 QC 通过）：
     - LLM 基于观测、环境、工具、历史生成动作；
     - 执行动作并记录结果；
     - 若修改了环境，则触发 QC 门控，将反馈写入历史。
- **证据工具（Table 1）**：
  - `select_views`：三级（房间/墙/物体）视角选择，房间级贪心选互补帧覆盖墙面，墙级按投影面积排序，物体级用渲染清单中的可见性找清晰视角，并设最小帧间距去重。
  - `render_and_compare`：用**同一标定相机**渲染并与照片配对，三级标注（房间级标物体名、墙级描墙轮廓、物体级画包围盒），使不一致可追溯到具体对象。
  - `measurement`：以米为单位测量尺寸与位置。
  - `stitch_wall`：将拍摄帧投影到度量墙面平面拼成正视参考图，并给出覆盖掩码与网格（沿墙距离 + 离地高度，红/蓝刻度）。
  - `fetch_material`：获取 PBR 贴图并可调整颜色。
  - `bash/glob/read/edit`：文件查找、读取代码与图像证据、创建/编辑程序。
- **作者化 harness 的四个有序模块**：① 匹配墙面材质；② 添加固定装置与光照；③ 放置小物体；④ 通过多视角渲染细化已有程序化资产的几何、外观与铰接。新增几何按命名对象分组，显式声明 `rests_on` 或 `attached_to` 关系。
- **控制与质量门控**：
  - **预算化控制**：会话设轮次与工具调用上限；最后 10% 调用禁用探索与自检，强制收尾保存；之后重建并验证。
  - **几何门控**：用网格相交判定真实碰撞（粗盒重叠不算），用凸近似估计修正位移；有界修正只移动未锚定物体，写回 `Room.py` 后重建复检。
  - **支撑门控**：比较物体底面与声明支撑面，报告缺失支撑或无效接触高度；检查铰接资产是否保留独立可动部件；间隙 >1 cm、穿透 >2 cm 为阻塞性发现，足印重叠不足一半需复核。
- **仿真就绪导出**：导出到 MuJoCo，每个物体带质量、惯量、碰撞几何与关节；墙与附着固定装置固定，可动物体用自由关节，铰接部件用铰链/滑动关节；碰撞形状分离以保留桌下与家具内部空间。

## 3. 实验设计

### 3.1 数据集 / 场景
- **10 个真实室内场景**，共 **620 个拍摄视角**（每场景 27–91 个视角）。
- 涵盖办公、厨房、会议室、图书馆、报告厅、卧室、花园房等（附录 A 展示 9 个房间）。
- 输入为 RGB-D 扫描 + 检测结果（RGB、深度与置信度、相机标定、派生点云、RoomPlan 布局）。

### 3.2 Benchmark 与评价协议
- **视觉保真度**：SSIM、PSNR、RMSE、LPIPS；所有重建对齐到录制相机坐标系（不改尺度与物体位姿），以 960×720 渲染；共 **3,720 次参考—渲染对比**（6 种方法–输入配置 × 同一场景–帧对）；保留全部 620 视角，逐帧等权平均。
- **几何一致性与物理合理性**：
  - Depth MAE（cm），在 611 个共享有效深度帧上计算；
  - Bottom near-contact：家具至少有一个采样底部点距外部支撑面 1 cm 内的比例；
  - Intersections：家具对之间三角形表面严格相交数（容差 0.1 mm）。
- **感知评估**：人类 + 两个智能体评估者（Agent-1、Agent-2），在布局准确度、物体相似度、整体场景相似度三个维度上 5 分制打分。
  - 人类：13 份有效提交，65 次参与者–场景评估，每方法每准则 65 个评分，共 780 个评分；匿名化 + 每场景位置随机化。

### 3.3 对比方法
- **LiteReality**（确定性流水线前作）。
- **Fable 5.1（Claude Code）**：RGB-only 与 +Scan 两种条件。
- **GPT-6 Astra（Codex）**：RGB-only 与 +Scan 两种条件。
- **LiteReality-Agent（本方法）**。
- 所有方法共用相同照片与相同扫描信息（+Scan 条件与 LiteReality/本方法一致），并共享各场景对应 LiteReality-Agent 场景的光照与色彩管理设置（保留各自材质与贴图）。

## 5. 实验数量与充分性

- **实验规模**：
  - 主实验：10 个场景 × 620 视角 × 6 种方法–输入配置 = 3,720 次图像对比；611 帧深度评估。
  - 感知评估：13 份人类提交、65 次场景评估、780 个评分；另加 2 个智能体评估者。
  - 布局修复统计：107 个输入框，29 个被移动、4 个被缩放；错误数从 30 降至 0；8 个场景需要修改、2 个原本有效未改。
  - 定性展示：MuJoCo 导出后的摇动测试、Franka 抓放示例；程序化编辑（地毯改色、清空区域、加吊灯）与自然语言编辑示例。
- **是否充分**：
  - **优点**：指标维度较全（视觉 + 深度 + 支撑 + 碰撞 + 人类 + 智能体），对比了确定性流水线与两类前沿通用智能体，并做了**扫描数据消融式对比**（RGB-only vs +Scan），能说明扫描信息的作用。
  - **不足**：
    - **无真正的消融实验**：论文自身承认「这些对比支持完整系统，但并未把 harness 与其他组件分离」，无法量化各模块贡献。
    - 人类样本小（13 人、65 次评估），场景覆盖不均（3–11 人/场景），作者明确表示**不构成统计显著性**。
    - 物体级指标（near-contact 率、相交对数）依赖各方法输出的家具数量，**群体不同**，需谨慎解读。
    - 智能体评分与人类评分绝对值存在差异，仅在前两名排序上一致。
  - **公平性**：相机对齐、分辨率、光照共享、无额外对齐/颜色校正等协议设计较为公平；但「共享光照来自 LiteReality-Agent 场景」对本方法可能略有偏向（作者也承认该光照未独立标定到参考照片）。

## 6. 主要结论与发现

- **视觉保真度**：LiteReality-Agent 在 SSIM（0.6105）、PSNR（14.129 dB）、RMSE（0.2033）、LPIPS（0.5392）四项指标上均最优；相比 GPT-6 (+Scan)，PSNR 提升 1.162 dB、LPIPS 降低 13.7%；相比 LiteReality，提升 2.248 dB、降低 19.6%。
- **几何一致性与物理合理性**：Depth MAE 10.50 cm（比 GPT-6 (+Scan) 低 21.2%）；86/86 家具物体底部近接触（100%）；家具–家具表面相交 **0 对**（LiteReality 为 43 对）。
- **扫描数据的作用**：加入 Scan 数据显著提升两个通用智能体的视觉指标（GPT-6 PSNR 11.549→12.967 dB，Fable 5.1 10.681→12.287 dB；深度 MAE 分别下降 67.1% 和 72.2%），但**并未一致改善物体级布局指标**（相交对反而增加，GPT-6 近接触率下降）。
- **感知评估**：LiteReality-Agent 人类均值最高（布局 4.60、物体 4.58、整体 4.54），在整体相似度上以 53 胜、11 平、1 负优于 GPT-6 (+Scan)；两个智能体评估者也都将其排第一。
- **可编辑性与仿真**：`Room.py` 支持程序化编辑（改色、删除家具、加吊灯）与自然语言指令编辑；导出 MuJoCo 后可摇动、可被 Franka 机械臂操作，说明分离刚体、支撑关系与关节使物理交互成为可能。
- **总体结论**：将重建表述为编码任务、配合 observe–edit–verify harness、专用工具与显式验证门控，能显著提升重建质量与可靠性；随智能体能力提升，该编排框架仍是有效的基础设施。

## 7. 优点

- **问题形式化新颖且实用**：把 3D 重建转成「编辑可执行程序」的编码任务，使场景天然可读、可复现、可编辑、可版本化，便于下游自然语言编辑。
- **观测锚定强**：所有工具都基于真实扫描证据（标定相机渲染对比、度量测量、墙面拼接 + 度量网格、PBR 材质检索），避免了纯语言先验生成「看似合理但不真实」的场景。
- **验证机制显式且分层**：几何门控（网格相交 + 凸近似修正）、支撑门控（底面/支撑面对比、间隙与穿透阈值）、碰撞与支撑分离检查，以及独立于评价指标的 QC 门控，设计严谨。
- **工程细节扎实**：有界修复预算（位移/尺寸上限、累计保真约束）、有界重试循环、预算化会话（最后 10% 调用禁用探索强制收尾）、程序化资产的物理属性来源标注（保留 provenance）。
- **端到端可仿真**：MuJoCo 导出考虑铰接关节、分离碰撞体、质量随体积缩放、惯量重算等，并给出摇动与机械臂操作演示。
- **评估维度全面**：视觉指标 + 深度一致性 + 支撑 + 碰撞 + 人类主观 + 智能体主观，并做了 RGB-only/+Scan 的输入条件对比。
- **开源**：源码与数据采集应用公开。

## 8. 不足与局限

- **物理属性缺乏真值验证**：质量、惯量、摩擦、恢复系数主要靠 LLM 推理与类别/材料先验估计，没有真实测量；仿真导出与一致性检查**不能证明**能复现真实世界动力学（作者明确指出）。
- **布局一致性 ≠ 布局正确性**：RoomPlan 检测本身的尺寸与位姿错误会残留在重建布局中；碰撞与支撑修正以及视觉一致性都不保证恢复真实布局，缺少与实测真值的对比。
- **缺乏组件消融**：无法分离 harness、布局修复、物理元数据估计等各部分的独立贡献。
- **感知评估样本有限**：13 份提交、65 次场景评估，场景覆盖不均，作者明确声明不构成统计显著性；智能体评分不能替代人类判断。
- **指标解释性风险**：物体级指标受各方法家具数量差异影响；碰撞计数需语义解读；深度 MAE 只反映部分物理合理性。
- **共享光照的潜在偏向**：所有方法共享来自本方法场景的光照设置，虽保留各自材质，但该光照未独立标定到参考照片。
- **评估场景规模有限**：仅 10 个室内场景，未覆盖更大、结构更多样化的环境；作者将更大规模、更多样环境的评估列为未来工作。
- **计算资源未报告**：缺少 GPU 型号、数量、训练/推理时长等关键信息，影响可复现性与成本评估。
- **应用限制**：依赖 LiteReality Scan 采集流程与 RoomPlan 检测质量；依赖前沿 LLM 智能体调用，成本与延迟未知；对遮挡区域的重建依赖生成模型估计而非真实观测。
