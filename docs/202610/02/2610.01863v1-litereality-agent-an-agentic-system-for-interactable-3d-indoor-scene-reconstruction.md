## 摘要
我们提出 LiteReality-Agent，一种智能体系统，可从 RGB-D 扫描中将真实室内环境重建为逼真、具有关节结构且可直接用于仿真的三维场景。其核心在于，LiteReality-Agent 将三维重建形式化为一个编码问题：编码智能体使用专用工具收集证据，并迭代编辑一个 Python 脚本 Room.py，执行该脚本即可生成房间的三维数字孪生。基于这一形式化，我们开发了一个稳健的“观察-编辑-验证”框架，在重建全过程中支持证据收集、测量、验证、布局优化、仿真就绪和质量控制。LiteReality-Agent 能生成适用于仿真及下游具身 AI 任务的高质量重建结果。此外，随着智能体能力持续快速提升，LiteReality-Agent 所引入的系统仍是未来智能体的强大编排框架：它为这些智能体配备了专用工具、结构化工作流和稳健的验证机制，从而显著提升重建质量与可靠性。我们证明，与近期前沿模型（如 Astra 和 Fable）生成的重建结果相比，LiteReality-Agent 生成的重建结果在几何上更准确、视觉上更逼真，并且与仿真更兼容。因此，我们将 LiteReality-Agent 视为构建稳健的真实到仿真（real-to-sim）系统的实用且重要的基础模块。源代码与数据采集应用均已公开。代码：https://github.com/LiteReality/LiteReality-Agent/

## Abstract
We present LiteReality-Agent, an agentic system for reconstructing real indoor environments as realistic, articulated, and simulation-ready 3D scenes from RGB-D scans. At its core, LiteReality-Agent formulates 3D reconstruction as a coding problem, in which a coding agent gathers evidence using specialised tools and iteratively edits a Python script, Room.py, which can be executed to produce a 3D digital twin of the room. With this formulation, we develop a robust observe-edit-verify harness that supports evidence gathering, measurement, verification, layout optimisation, simulation readiness, and quality control throughout the reconstruction process. LiteReality-Agent produces high-quality reconstructions suitable for simulation and downstream embodied AI tasks. Furthermore, as agent capabilities continue to improve rapidly, the system introduced by LiteReality-Agent remains a strong orchestration framework for future agents: it equips them with specialised tools, structured workflows, and robust verification mechanisms that substantially improve reconstruction quality and reliability. We demonstrate that LiteReality-Agent produces reconstructions that are more geometrically accurate, visually realistic, and simulation-compatible than those generated by recent frontier models, such as Astra and Fable. We therefore view LiteReality-Agent as a practical and important building block for robust real-to-sim systems. Both the source code and the data-capture application are publicly available. ## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：如何从消费级 RGB-D 室内扫描中，重建出**几何准确、可交互、且直接可用于物理仿真**的结构化三维数字孪生，而非仅得到点云或网格。
- **为何困难**：这要求同时完成场景结构理解、物体及其铰接结构重建、材质与物理属性估计、空间关系解析，并整合为一个鲁棒端到端系统。
- **已有路线及其不足**：
  - CAD 检索对齐（Scan2CAD、Mask2CAD、DiffCAD）——表示紧凑，但依赖模型库、难以覆盖真实杂乱场景。
  - 组合式三维重建 / 逆渲染（CAST、PhotoScene、PSDR-Room）——多针对单图或少数图像，规模与鲁棒性有限。
  - **LiteReality**——多阶段流水线，可把扫描转为图形就绪场景，但流程高度确定性，难以处理预定义场景之外的情况。
  - LLM 场景生成（Holodeck、SceneCraft、SceneSmith、Articraft）——可产出仿真就绪环境，但**缺少一个能把智能体输出锚定到真实观测、并保证质量一致的系统**。
- **整体含义**：论文主张当前缺的不是更强的模型，而是一个**编排框架**——用专用工具、结构化工作流和验证机制约束编码智能体，使其在真实扫描上稳定产出高质量 real-to-sim 资产。

## 2. 方法论

### 2.1 核心思想
- 把三维重建**形式化为编码任务**：整个房间表示为一个可执行的 Python 程序 `Room.py`，作为智能体的持久化工作区。
- 智能体通过工具读取观测、编辑程序、编译重建场景；所有修改都经过同一可执行表示，保证场景**可读、可复现、可直接编辑**，并天然支持后续自然语言编辑。
- 系统分两阶段：**Scene Initialisation**（建立布局与主要物体）+ **Agentic Authoring**（观察-编辑-验证闭环精修）。

### 2.2 阶段一：Scene Initialisation
- **输入**：LiteReality Scan 应用提供的 RGB-D 扫描、深度与置信度、相机内外参、点云，以及 RoomPlan 检测的房间结构与语义包围盒。
- **Layout Agent**：
  - 用**场景图**表示结构面、开口与物体，关系区分**物理支撑**（椅子由地板支撑）与**功能归属**（椅子属于桌子），并区分不兼容重叠与预期包围（椅子塞入桌下）。
  - 几何检查识别房间外、嵌入墙内、无支撑、不兼容重叠的检测框。
  - **确定性修复**（墙对齐、角落拟合、分离、小幅尺寸调整）+ **图像推理**处理模糊情形（尺寸错误、误合并检测）。
  - 修复受**保真上限**约束：水平位移 ≤ 0.6 m、垂直 ≤ 0.08 m；桌子/椅子等类别尺寸变化 ≤ 15%，其他类别 ≤ 35%；不得删除已测量物体；最多六轮智能体辅助修复。
  - 实测：30 个错误降至 0；10 个场景中 8 个需要修改，107 个输入框中 29 个被移动、4 个被缩放。
- **物体重建**：
  - 选定捕获视图 → 图像生成模型生成干净参考图。
  - **结构化/铰接物体**走程序化生成（沿用 Articraft 思路：编码智能体编写 `object.py`，定义几何、独立运动部件与关节）；**视觉复杂的静态物体**用 TRELLIS.2 图像到三维生成。
  - 网格质检：异常长宽比、断裂碎片、大面积平坦边界、底部密集几何（疑似融合地板/背景）；椅子有有界重试循环（重生成参考图与网格、更换随机种子）。
  - 物理属性编译：作者指定质量优先，否则按类别占用密度 × 包围盒体积估计质量，按几何计算惯量与质心，按材料名先验给摩擦/恢复系数；凸包或凸分解生成碰撞几何，并做逐物体 MuJoCo 短程掉落、关节释放、倾斜滑动检查。
- **场景程序**：壳体与重建物体按校正后的尺度位姿组装为 `Room.py`，定义房间、物体实例、材质与附加几何。

### 2.3 阶段二：Agentic Authoring
- **循环流程（Algorithm 1）**：观测 → LLM 产生动作 → 执行动作并更新历史 → 若编辑了环境则执行 QC → 未通过则继续，直到轮次上限或 QC 通过。
- **证据工具（Table 1）**：
  - `select_views`：支持**房间 / 墙 / 物体**三级视图选择；房间级贪心选互补帧覆盖墙面，墙级按投影屏幕面积排序，物体级按渲染清单中的可见性选清晰视图，并设最小帧间隔去重。
  - `render_and_compare`：渲染与照片使用**同一标定相机**；房间视图标注可见物体名，墙视图只勾勒选中墙，物体视图画包围盒，便于逐级定位差异。
  - `stitch_wall` + `measurement`：把捕获帧投影到度量墙面平面拼接成正视参考图并给出覆盖掩码；叠加网格表示沿墙距离与离地高度（红/蓝刻度），可直接读出白板等固定装置的坐标与尺寸。
  - `fetch_material`：获取 PBR 贴图并可调色以匹配观测。
  - `bash/glob/read/edit`：文件与代码操作。
- **Authoring Harness 四个有序模块**：① 匹配墙面材质 → ② 添加固定装置与照明 → ③ 放置小物体 → ④ 用多视图渲染细化已有程序化资产的几何、外观与铰接。新增几何归入具名物体并声明 `rests_on` / `attached_to` 关系。
- **控制与质量门**：
  - **预算控制**：会话有轮次与工具调用上限；最后 10% 调用禁用探索与自检，强制完成并保存编辑；程序重建后仍需验证。
  - **几何门**：用网格相交判定碰撞（而非包围盒），凸近似估计校正平移，在有限预算内水平移动未锚定物体，写回 `Room.py` 后重建复检。
  - **支撑门**：比较物体底面与声明支撑顶面及足迹重叠；间隙 > 1 cm 或穿透 > 2 cm 为阻塞性发现，足迹重叠不足一半需复核，缺失/未知支撑声明也阻塞。
- **仿真导出**：导出 MuJoCo，墙体与附着固定装置固定，可移动物体为自由关节，铰接部件用铰链/滑动关节；独立碰撞形状保留桌下与柜内空间；尺寸变化时质量按体积缩放、作者指定质量保留、惯量按放置后几何重算。

## 3. 实验设计

- **场景与数据**：10 个真实室内场景，共 **620 个捕获视图**（每场景 27–91 个），611 帧有共享有效深度。输入为 RGB-D 扫描 + RoomPlan 布局（含语义类别、尺寸、位置、朝向）。
- **Benchmark / 对比方法**：
  - **LiteReality**（确定性流水线基线）
  - **GPT-6 Astra**（Codex 中运行）
  - **Fable 5.1**（Claude Code 中运行）
  - 两个通用智能体各在 **RGB-only** 与 **+Scan**（深度、标定、点云、RoomPlan 布局）两种输入下评估；LiteReality 与 LiteReality-Agent 接收与 +Scan 基线相同的扫描信息，所有方法使用相同照片。
- **评估协议**：
  - 所有重建对齐到记录相机坐标系，不改场景尺度与物体位姿；用记录位姿与内参渲染 960×720；**在捕获视点而非新视角**评估。
  - 所有方法共享来自对应 LiteReality-Agent 场景的灯光与色彩管理设置，但保留各自材质、纹理与材质发光；该光照**未独立校准到参考照片**。
  - 共 3,720 次参考-渲染配对比较（6 种方法-输入配置 × 场景-帧对）。
- **三类指标**：
  - **视觉保真**：SSIM、PSNR、RMSE、LPIPS（无额外对齐或外观校正，逐帧等权平均）。
  - **几何一致性与物理合理性**：Depth MAE（cm，611 帧）、bottom near-contact（至少一个采样底部点在外部支撑面 1 cm 内的家具占比）、家具对三角形表面相交数（0.1 mm 容差）。
  - **感知评估**：人类（13 份有效提交、每方法 65 个评分）与两个智能体评估者（Agent-1、Agent-2），在布局准确性、物体相似性、整体场景相似性三个维度上 5 分制打分；方法匿名、位置随机化。
- **定性展示**：厨房与会议室的重建对比；MuJoCo 中的摇晃与 Franka 抓取放置；程序化编辑（地毯改色、清除区域、加吊灯）与自然语言编辑（露出砖墙、清空场地开会、装饰看世界杯）。
