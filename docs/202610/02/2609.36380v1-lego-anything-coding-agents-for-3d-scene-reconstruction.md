## 摘要
由单张图像重建的三维场景，其最有用的表示形式并非渲染结果或固定的三维输出，而是一个显式的场景程序，其执行可生成一个可检查、可编辑、可查询的场景。我们提出 LEGO-Anything，一个 Image-to-Code 框架，其中编码智能体迭代地编写并执行 Blender 代码，检查场景与渲染结果，并修订程序。为评估端到端场景恢复，我们提出 LEGO-Bench，一个基于仿真器的基准，包含来自 104 个多样化室内外场景的 208 张图像。LEGO-Bench 分别对产物有效性、可见表面几何与渲染外观进行评分。其基于仿真器的设计使其具备可扩展性，并支持精确的自动评估。在受评估的智能体中，GPT-6-astra 取得最强的整体结果，室内和室外得分分别为 53.4% 和 39.6%，但在生成有效的场景产物与忠实恢复场景几何和外观之间仍存在显著差距。对智能体构建轨迹的分析揭示了三个反复出现的问题：场景初始化薄弱、迭代过程中的退化性编辑，以及不可靠的自我评估。这些发现促成了 LEGO-Plugin，一个免训练的 harness 插件，用于更可控的迭代式场景构建；它提升了所有六个受评估模型，整体得分的相对提升最高达 62.7%。最后，我们测试重建场景能否表示自然图像并支持视觉任务。在 LEGO-World 中，我们将目标检测、实例掩码和相对深度作为对 GPT-6-astra 重建场景的确定性查询来导出。这些读出结果在全部三个任务上均表现出非平凡的性能，但远不及专用视觉模型，这表明由当前编码智能体构建的程序化场景是一种有前景但尚不够精确的自然图像表示。

## Abstract
A 3D scene reconstructed from a single image is most useful when represented not as a rendering or a fixed 3D output, but as an explicit scene program whose execution yields a scene that can be inspected, edited, and queried. We present LEGO-Anything, an Image-to-Code framework in which a coding agent iteratively writes and executes Blender code, inspects scenes and renderings, and revises the program. To evaluate end-to-end scene recovery, we introduce LEGO-Bench, a simulator-grounded benchmark with 208 images from 104 diverse indoor and outdoor scenes. LEGO-Bench separately scores artifact validity, visible-surface geometry, and rendered appearance. Its simulator-grounded design enables extensibility and precise automatic evaluation. Among evaluated agents, GPT-6-astra achieves the strongest overall results, with 53.4% indoor and 39.6% outdoor scores, yet substantial gaps remain between delivering valid scene artifacts and faithfully recovering scene geometry and appearance. Analysis of agent construction trajectories reveals three recurring issues: weak scene initialization, regressive edits during iteration, and unreliable self-evaluation. These findings motivate LEGO-Plugin, a training-free harness plugin for more controlled iterative scene construction, which improves all six evaluated models, with relative gains of up to 62.7% in overall score. Finally, we test whether reconstructed scenes can represent natural images and support vision tasks. In LEGO-World, we derive object detections, instance masks, and relative depth as deterministic queries on scenes reconstructed by GPT-6-astra. These readouts show non-trivial performance across all three tasks but fall well short of specialized vision models, suggesting that program-constructed scenes from current coding agents are a promising but not yet sufficiently precise representation of natural images.

- **整体含义**：论文把单图场景重建重新定义为 **Image-to-Code（Image2Code）** 问题，并用通用**编码智能体（coding agent）**来实例化这一表示，从而研究三个问题：
  1. 编码智能体从单图重建场景的忠实程度如何；
  2. 是什么限制了它们的迭代构建过程；
  3. 重建出的场景程序是否足够精确，可以作为自然图像的表示并支持下游视觉任务。

## 2. 方法论

### 2.1 LEGO-Anything：场景重建即 Image-to-Code

- **形式化**：给定单张 RGB 图像 $I$，通用编码智能体 $\pi$ 与三维编辑环境 $E$（此处为 Blender）交互，产出场景程序 $P$，执行后构造场景 $S$：
  - $P = \pi(I; E)$，$S = \mathrm{Exec}_E(P)$。
- **非一次性生成**：智能体在「编辑代码 → 执行 → 检查场景与渲染」之间交替，形成构建轨迹 $\tau = \{(P_t, S_t, o_t)\}_{t=1}^{T}$，最终 $P = P_T$。
- **提交产物**：最终场景、导出文件（scene.glb）、一张渲染图，三者共同构成可评估保真度、可查询下游感知的**可执行产物**。

### 2.2 智能体工作流（图 2 抽象自 GPT-6-astra 轨迹）

- **Agent Workspace**：管理 `scene.blend`（可编辑）、`scene.glb`、`final.png`、`app`（只读）、`README.md`。
- **Action Space**：读文件、规划、写代码、执行、检查、持久化。
- **Blender Code Structure**：文件元数据、渲染设置、场景活动相机、对象（网格/曲线）、外观、层级、文本块。
- **Construction Workflow（11 步）**：输入图像与任务规范 → 环境与产物初始化 → 参考图像解读 → 语义场景分解 → 构建规划 → Blender Python 合成 → 执行代码 → 预览渲染 → 视觉评估 → 代码评估（结构匹配、连接有效、无碰撞、物理稳定）→ 最终产物（PASS/FAIL 分支回环）。

### 2.3 LEGO-Bench 评估指标

- **Validity $V_i$**：`scene.blend` 能打开且含可渲染几何与活动相机、`scene.glb` 合法非空、`final.png` 可解析非退化。失败者记 $V_i=0$ 且 $R_i=A_i=0$（**低质量本身不算无效**）。
- **Reconstruction $R_i$**：只比较参考视图中**可见表面**的几何一致性。提交场景在自身活动相机下提取可见面，参考侧由私有深度反投影得到；两组点投影到图像平面后由私有实例掩码划分到对象，**在相机坐标系下直接比较，不做任何对齐或缩放**。逐对象精度/召回用深度相对容差 $\tau(g)=0.05\,z(g)$，对象 F1 后做等权宏平均得 **F@5%**；另有 F@2%（更严）与 F@10%（更松）辅助指标。
- **Appearance $A_i$**：**评估器重新渲染**提交场景（固定渲染引擎与分辨率，保留其相机/几何/材质/光照/色彩），像素在某通道误差不超过 $\delta=30$（0–255）即计为正确，正确像素比例即得分。
- **总分**：有效提交取 $S_i = \frac{1}{2}(R_i + A_i)$，无效或评估失败记 0；基准分对所有尝试样本取平均（含失败）。

### 2.4 LEGO-Plugin：从失败诊断到可控构建

- **三个失败诊断**（来自轨迹分析）：
  1. **初始化薄弱**：较弱智能体迟迟不产出可评估场景（GPT-5.6-sol 需约 1/5 预算，GPT-6-astra 约 1/10）；
  2. **退化性编辑**：GPT-5.6-sol 有 29.6% 的编辑使分数下降，最终提交比最佳中间场景低 3.2 分；
  3. **自评不可靠**：几何判断接近或低于随机（自评 45.8%，交叉 45.4%，随机为 50%）。
- **插件设计（免训练，作为 MCP 工具 / 工作流技能 / 运行时钩子接入，不替代 agent 规划器）**：
  - **Enhanced Initialization**：用 VGGT 从参考图恢复场景帧与相机，推导可见对象布局线索，形成显式初始化提案（有意避免度量深度与绝对尺寸）；
  - **Grounded Refinement**：用 SAM 3 提取参考对象区域、Depth Anything V2 提取相对深度，把执行场景与这些目标通过**显式残差**（投影范围、相对深度、深度序、渲染亮度等）比较，取代自由形式的自我纠正；
  - **Version Control**：每次编辑作为事务（声明可编辑/受保护实体、允许变更类型、验收要求），提交前快照，事后校验，未通过则回滚；每例最多 8 次事务、2 次回滚。
  - **关键约束**：插件只使用参考图像与当前 Blender 场景，**从不访问基准私有真值或 LEGO-Bench 分数**。

### 2.5 LEGO-World：重建场景作为视觉表示

- 对任务 $k$，确定性读出 $\rho_k$ 从冻结场景得到预测：$I \to P \to S \to \hat{y}_k$。
- 可见对象实例投影为二维框（检测）与实例掩码（分割），相机空间深度渲染提供相对深度。

## 3. 实验设计

### 3.1 基准与数据

- **LEGO-Bench**：基于 **LychSim** 仿真器 + **Fab** 资产库构建，208 张 RGB 输入、104 个逻辑场景、8 个环境、17 个主题、443 个注册资产（仅选用允许 AI 使用的资产）。
- **难度控制**：同族场景内对象集合嵌套（Easy ⊂ Medium ⊂ Hard），架构、材质、光照、相机及共享对象属性固定，仅增加可见内容；候选场景经碰撞/稳定性检查与人工审核。
- **额外拆分**：NYC 鸟瞰（Bird's-Eye）10 例大规模压力测试，无难度配对，不计入配对复杂度分析。
- **任务输入**：仅提供 RGB 图与公开元数据（图像尺寸、水平 FOV、类别体系、输出 schema）；参考几何、深度、实例掩码、对象对应与场景变换均为评估器私有。
- **人类验证**：6 名标注者、240 个样本、960 个局部区域；标注者间兼容一致性 86.6%（重建 88.9%、外观 84.3%），人–指标兼容一致性 83.7%。

### 3.2 对比方法

- **通用编码智能体（6 个，均在 Codex harness 下）**：GPT-6-astra / GPT-6-sol / GPT-6-luna、GPT-5.6-sol / GPT-5.6-terra / GPT-5.6-luna。
- **任务专用 LLM 系统**：VIGA（仅程序化设置，禁用外部资产生成）、SceneConductor（仅室内）。
- **单图场景构建基线**：3D-RE-GEN（仅室内，PLY 转 Blender）、Gen3DSR、REST3D（仅室内）、SceneGen。
- 所有方法共享同一冻结评估器；对不支持的任务留空。

### 3.3 主要实验组

| 实验 | 设置 |
|---|---|
| 主基准对比 | 室内/室外两个拆分，每配置 **3 次独立运行**，报均值±标准差 |
| 场景复杂度分析 | Easy / Medium / Hard 三档 × 室内外 |
| 测试时扩展 | 42 例 Office 子集，6 模型 × 4 档推理强度（Low/Medium/High/XHigh），共 1008 个结果 |
| 轨迹诊断 | GPT-6-astra、GPT-5.6-sol/terra/luna，每队列 198 个室内外任务（排除 10 个鸟瞰） |
| VLM 判官 | 6 builder × 6 judge = 36 对，360 个 checkpoint 对，2160 次主判断 + 216 次顺序交换审计 |
| LEGO-Plugin | 42 例 Office 子集，6 模型 with/without 对照 |
| LEGO-World | COCO val2017、LVIS v1 val、ETH3D 各 100 张图 |
| 附加分析 | 成本–性能帕累托前沿、鸟瞰压力测试、场景级关节（articulation）试点评估 |

### 3.4 主要数值结果

- **主基准**：GPT-6-astra 最强，室内 V/R/A/S = 100.0 / 52.4 / 54.4 / **53.4**，室外 98.0 / 34.0 / 45.5 / **39.6**；最强的 GPT-5.6 配置仅 15.4%（室内）/ 15.3%（室外）。
- **基线特征**：Gen3DSR 重建分高于 GPT-6-astra（室内 65.4 vs 52.4）但外观为 0；VIGA、3D-RE-GEN 产物有效但保真度低；SceneConductor 有效性仅 12.3%。
- **LEGO-Plugin**：6 个模型全部提升，GPT-5.6 三个模型提升 55–63%（约 7–8 分），GPT-6-luna +27.5%、GPT-6-sol +12.1%、GPT-6-astra 仅 +2.1%（最高相对增益 62.7%）。
- **LEGO-World**：检测 30.14 box AP（DINO 59.88）、分割 14.75 mask AP（SAM 3 53.96）、深度 0.1554 AbsRel（Depth Anything 3 0.0783）。
