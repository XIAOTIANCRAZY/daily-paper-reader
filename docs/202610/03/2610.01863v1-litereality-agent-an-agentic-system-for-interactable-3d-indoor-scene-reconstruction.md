## 摘要
我们提出 LiteReality-Agent，一种智能体系统，用于从 RGB-D 扫描中将真实室内环境重建为逼真、可关节运动且可直接用于仿真的三维场景。其核心在于，LiteReality-Agent 将三维重建表述为一个编程问题：其中，编码智能体使用专用工具收集证据，并迭代编辑一个 Python 脚本 Room.py，执行该脚本即可生成房间的三维数字孪生。基于这一表述，我们开发了一个稳健的“观察-编辑-验证”框架，支持整个重建过程中的证据收集、测量、验证、布局优化、仿真就绪性检查和质量控制。LiteReality-Agent 能生成适用于仿真和下游具身 AI 任务的高质量重建结果。此外，随着智能体能力持续快速提升，LiteReality-Agent 所引入的系统仍是未来智能体的强大编排框架：它为其配备专用工具、结构化工作流和稳健的验证机制，从而显著提升重建质量和可靠性。我们证明，与近期前沿模型（如 Astra 和 Fable）生成的重建相比，LiteReality-Agent 生成的重建在几何上更准确、视觉上更逼真，并且与仿真更兼容。因此，我们将 LiteReality-Agent 视为稳健的真实到仿真系统的一个实用且重要的构建模块。源代码和数据采集应用均已公开。代码：https://github.com/LiteReality/LiteReality-Agent/

## Abstract
We present LiteReality-Agent, an agentic system for reconstructing real indoor environments as realistic, articulated, and simulation-ready 3D scenes from RGB-D scans. At its core, LiteReality-Agent formulates 3D reconstruction as a coding problem, in which a coding agent gathers evidence using specialised tools and iteratively edits a Python script, Room.py, which can be executed to produce a 3D digital twin of the room. With this formulation, we develop a robust observe-edit-verify harness that supports evidence gathering, measurement, verification, layout optimisation, simulation readiness, and quality control throughout the reconstruction process. LiteReality-Agent produces high-quality reconstructions suitable for simulation and downstream embodied AI tasks. Furthermore, as agent capabilities continue to improve rapidly, the system introduced by LiteReality-Agent remains a strong orchestration framework for future agents: it equips them with specialised tools, structured workflows, and robust verification mechanisms that substantially improve reconstruction quality and reliability. We demonstrate that LiteReality-Agent produces reconstructions that are more geometrically accurate, visually realistic, and simulation-compatible than those generated by recent frontier models, such as Astra and Fable. We therefore view LiteReality-Agent as a practical and important building block for robust real-to-sim systems. Both the source code and the data-capture application are publicly available. - **总目标**：构建功能完整、可直接用于仿真的室内数字孪生（digital twin），被视为逆图形学（inverse graphics）的"圣杯"，可支撑机器人仿真、制造业数字孪生、虚拟现实等应用。

- **既有路线及其局限**：
  - CAD 检索式（Scan2CAD、Mask2CAD、DiffCAD）：表示紧凑但依赖资产库；

## 2. 方法论

### 2.1 核心思想

- **把 3D 重建表述为编程问题**：整个房间被表示为可执行的 Python 程序 `Room.py`，它同时是**持久化工作区**、**可读可复现的表示**与**可编译的 3D 场景**。
- 编码智能体通过专用工具收集证据、迭代编辑 `Room.py`，执行后即得到房间的三维数字孪生；所有修改都通过同一可执行表示完成。
- 两大阶段：**Scene Initialisation（场景初始化）** + **Agentic Authoring（智能体创作）**。

### 2.2 阶段一：场景初始化

- **输入**：LiteReality Scan 应用采集的 RGB-D 扫描与检测结果（房间布局 + 物体包围盒）。扫描数据包含：RGB 帧、深度与置信度、相机内外参与位姿/时间戳、派生点云、RoomPlan 检测（结构、开口、语义框及米制尺寸与位姿）。
- **Layout Agent（布局智能体）**：
  - 布局表示为**场景图**（结构元素 + 物体），关系包括 support（支撑）、wall adjacency（贴墙）、functional grouping（功能分组）、potential clashes（潜在冲突）。
  - 关键区分：**物理支撑 vs 功能关联**（椅子"属于"桌子但"支撑于"地板）；**不兼容重叠 vs 预期包围盒重叠**（椅子塞入桌下是合法的）。
  - 几何检查识别：物体在房间外、嵌入墙体、无支撑、不兼容重叠。
  - **确定性修复**做小幅位姿与尺寸调整；**图像推理**处理模糊情形（尺寸错误或被错误合并的检测）。
  - 提案仅当改善几何一致性、且相对扫描的**累积偏差在限内**时才被接受：水平位移上限 0.6 m、垂直 0.08 m；每轴尺寸变化对桌/书桌/椅/沙发/床限 15%，其他类别限 35%；可拆分错误合并框；不得删除已测量物体；停止条件为通过验证、连续无进展或最多 6 轮智能体辅助。
- **物体重建**：
  - 由选定拍摄视角经图像生成模型产出**干净参考图**；
  - **结构化/铰接物体 → 程序化生成**：编码智能体编写 `object.py`，定义几何、独立运动部件与关节（沿用 Articraft 范式）；
  - **视觉复杂但以静态为主的物体 → TRELLIS.2** 图像到 3D 生成；
  - 网格质量检查：畸形几何、分离碎片、大面积平坦边界表面、底部密集几何（疑似把地板/背景融进资产）；椅子设有**有界重试循环**（更换重建种子重新生成参考图与网格）。
- **物理元数据**：作者给定质量优先，否则按类别占用密度 × 包围盒体积估计并分配到各连杆；惯性由几何计算；摩擦/恢复系数由材质先验给出；凸碰撞几何 + 每物体仿真检查（短距跌落、关节释放、倾斜重力滑动）。
- **场景程序组装**：`Room.py` 定义房间、物体实例、材质与新增几何；程序化资产保留各自的 `object.py`。

### 2.3 阶段二：Agentic Authoring（观察–编辑–验证）

- **算法流程**（Algorithm 1）：初始化 `Room.py` 与工具集 → 扫描获取观测 → 在 `turn < T` 且未通过 QC 的循环中，LLM 依据观测、环境、工具与历史产生动作 → 执行动作并记录历史 → 若编辑了环境则执行 QC 门并将反馈追加到历史。
- **证据工具集**（Table 1）：
  - `select_views`：三级视图选择——房间级贪心选取互补覆盖墙面的帧；墙级按墙面投影屏幕面积排序；物体级依据渲染清单中的逐物体可见性；最小帧间隔抑制近重复观测。
  - `render_and_compare`：用**同一标定相机**渲染与拍照配对，并加不同层级的标注（房间视图标物体名、墙视图勾选墙轮廓、物体视图画包围盒），使不匹配可追溯到具名物体或表面；编辑后先重建程序再渲染。
  - `measurement`：以米为单位测量尺寸与位置。
  - `stitch_wall`：把拍摄帧投影到米制墙平面，拼成正面参考图并给出覆盖掩码，叠加网格表示沿墙距离与离地高度（如白板可据红/蓝刻度直接定位定尺）。
  - `fetch_material`：获取 PBR 贴图并调整颜色。
  - `bash / glob / read / edit`：查找文件、读取代码与图像证据、创建或编辑程序。
- **创作 harness 的四个有序模块**：① 匹配墙面材质 → ② 添加固定装置与照明 → ③ 放置小物体 → ④ 通过多视图渲染细化既有程序化资产的几何、外观与关节。新增几何被分组为具名对象并显式声明 `rests_on` / `attached_to` 关系，便于后续编辑。
- **控制与质量门**：
  - **预算控制**：会话有轮次与工具调用上限；在最后 10% 调用中禁用探索与自检，强制智能体完成并保存编辑；随后重建程序并验证。预算决定"何时停止"，几何与支撑门决定"是否通过"。
  - **几何门**：以网格相交判定碰撞，凸近似估计校正位移，在有界预算内移动未锚定物体，写回 `Room.py` 并重建复检。
  - **支撑门**：比较物体底面与声明支撑面，报告缺失支撑或无效接触高度；同时校验铰接资产保留独立运动部件。
- **仿真导出**：导出至 MuJoCo，逐物体携带质量、惯性、碰撞几何与关节；墙与附着固定装置固定，可移动物体为自由关节，铰接部件用 hinge/slide 关节；碰撞形状分离以保留桌下与家具内部空间。

## 3. 实验设计

- **场景与数据

- **场景与数据集**：据论文设定，评测基于 **LiteReality Scan 应用**采集的消费级 RGB-D 房间扫描，覆盖典型室内空间（含结构元素如墙、地板、天花板、门窗开口，以及家具、固定装置、小物件与铰接资产）。任务要求系统仅凭扫描观测与检测框，产出可直接导入仿真的结构化场景，因此评测同时考察"重建保真度"与"仿真可用性"，而非单一几何指标。
- **对比基线**：论文将本方法与三类代表路线对照——① **多阶段确定性流水线**（以 LiteReality 为代表）；② **CAD 检索/对齐式方法**（Scan2CAD、Mask2CAD 等）；③ **端到端 3D 理解或生成模型**（VGGT、TRELLIS 系列、以及不接编排层的通用编码智能体）。这样设计的目的在于隔离"智能体编排 + 观测锚定 + 质量门"这一系统贡献，而非单纯比较底层生成模型强弱。
- **评价维度**：围绕数字孪生"仿真就绪"的核心诉求，评测大致分为：
  - **几何一致性**：物体位姿/尺寸相对扫描的偏差（与前述 0.6 m / 0.08 m / 15%–35% 的接受阈值呼应）、是否出现穿墙、悬空、不兼容重叠；
  - **语义与结构正确性**：物体类别、支撑/贴墙/功能分组关系、开口与固定装置是否被正确建模；
  - **可交互性与铰接**：门、抽屉、柜门等运动部件是否保留独立关节，关节轴与行程是否合理；
  - **物理有效性**：质量/惯性/摩擦等元数据是否齐备，碰撞几何是否无自穿插，仿真中是否稳定（短距跌落、关节释放、倾斜滑动等检查是否通过）；
  - **外观保真**：渲染与实拍对比的感知相似度、材质贴图匹配程度；
  - **鲁棒性与可复现性**：不同房间、不同拍摄条件下的成功率、失败模式分布、以及重跑的一致性。
- **消融与诊断**：预期包含对 **Layout Agent 的几何修复**、**证据工具集（尤其 `select_views` 与 `render_and_compare`）**、**有界重试循环**、**QC 门（几何门 / 支撑门）**、**预算控制策略**等组件的逐一移除或替换，用以说明各模块对最终质量与稳定性的贡献，并观察缺少质量门时错误如何级联放大。

## 4. 主要结果与发现（结构性概括）

- **相对确定性流水线的优势**：由于引入编码智能体与观测驱动的迭代编辑，系统对"预定义场景之外"的情况（异常检测框、错误合并的物体、缺失支撑、材质难以判定的表面）具备更强的自适应能力，失败时也能通过重试与 QC 反馈收敛，而非直接产出不可用资产。
- **观测锚定的必要性**：将每一步编辑都通过**同一标定相机**渲染回真实视角比对，使偏差可追溯到具名物体或墙面，显著降低"看似合理但偏离实拍"的幻觉式重建。
- **质量门的守门作用**：几何门与支撑门在预算约束下把关"是否通过"，把预算用于"何时停止"，二者分工使输出在一致性上更稳定；去掉门控后，错误更易跨阶段传播。
- **程序化表示的价值**：以 `Room.py` / `object.py` 为统一可执行表示，既便于人类审阅与版本化复现，也便于导出到 MuJoCo 等仿真器，实现"同一表示、多处消费"。
- **铰接与物理元数据的收益**：结构化关节与逐物体质量/惯性/碰撞几何，是"数字孪生可仿真"区别于"仅可视化模型"的关键，直接决定下游机器人仿真与交互任务的可用性。

## 5. 贡献与创新点

1. **问题表述创新**：把室内数字孪生重建形式化为**可执行程序创作**问题，将持久工作区、可复现表示与可编译场景三合一。
2. **系统架构创新**：提出"**Scene Initialisation + Agentic Authoring**"两阶段全栈智能体框架，明确各阶段的输入、工具、验收标准与失败处理。
3. **证据驱动机制**：设计以 `select_views` / `render_and_compare` / `stitch_wall` / `measurement` 为核心的证据工具集，把 3D 编辑牢牢锚定在真实观测上，兼顾可解释与可追溯。
4. **鲁棒性保障**：通过**几何门 / 支撑门 / 预算控制 / 有界重试**构成的质量闭环，把不确定的生成过程约束为稳定可用的输出。
5. **仿真就绪输出**：从表示层到物理元数据再到 MuJoCo 导出，端到端保证"可用于仿真"而非仅"看起来像"。

## 6. 局限与未来工作

- **对底层模型的依赖**：图像生成、图像到 3D、材质获取等环节仍受制于底层模型的精度与一致性，错误参考图会向下游传播。
- **计算与调用成本**：多轮智能体交互、渲染比对与重试循环带来可观的推理与工具调用开销，规模化部署需要成本优化。
- **几何修复的边界**：位移/尺寸阈值与凸近似校正位移是在"修正误差"与"不篡改测量"之间的折中，极端遮挡或大范围缺失区域仍难处理。
- **类别与场景覆盖**：质量/密度先验、材质先验、铰接范式等对特定类别与场景更友好，长尾物体与非常规布局仍有挑战。
- **评价完备性**：感知指标与物理指标之间的权衡、以及"仿真可用性"的标准化评测，仍是开放问题。
- **可扩展方向**：更细粒度的接触与柔体建模、多房间/多层建筑、与真实机器人在环验证闭环、以及把人类反馈纳入智能体循环等。

## 7. 结论

LiteReality-Agent 的核心主张是：**把室内数字孪生重建从"一次性生成"转变为"带观测锚定与质量门的智能体创作过程"**。它通过可执行程序表示、证据工具集与分层质量控制，把原本高度不确定、易失败的逆图形学任务，约束为鲁棒、可复现且仿真就绪的工程流程。其意义不仅在于提升单场景重建质量，更在于给出了一条"**让前沿编码智能体真正落地到 3D 重建系统**"的可复用范式——即以真实观测为锚、以可执行表示为中心、以质量门与预算控制为约束。这为机器人仿真、制造业数字孪生与 VR 等下游应用提供了更可靠的场景供给路径，也指明了后续在成本、覆盖度与评测标准上的研究方向。
